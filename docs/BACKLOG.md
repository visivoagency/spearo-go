## Open

### Tide backend (`tidesGo`)
Designed and approved, not built. See
`docs/superpowers/specs/2026-08-31-tide-accuracy-design.md`. NOAA for US waters,
WorldTides worldwide, behind a public HTTPS function with App Check, rate
limiting and a daily credit ceiling. Clients stay thin — the function owns the
source choice, so Swift and Kotlin cannot drift the way the two `TideService`
files already did once.

Deploy **by name** (`firebase deploy --only functions:tidesGo`). The Firebase
project is shared with three other apps.

### A landlocked spot still gets a dive verdict
With marine and tides both correctly reporting nothing, the verdict is computed
from weather and solunar alone — so Queidersbach, 400 km inland, still reads
"GO". Honest arithmetic, questionable product. Decide whether a location with no
marine coverage should get a verdict at all, or say "no sea here".

### Swift has no test target
The Kotlin side has 8 JUnit tests. The Xcode project is generated by
`generate_xcodeproj.py` and has no test target, so Swift correctness is
currently verified by running the shipping code standalone. The tide spec (§4)
requires the same golden fixture in both languages, so this has to be built
before that lands.

### Store listings still claim offline tides
`README.md`, `docs/APP_STORE_METADATA.md` and `docs/GOOGLE_PLAY_METADATA.md` all
advertise "offline tide calculations". Solunar remains genuinely offline; tides
no longer are, and right now are absent. Must be rewritten before submission.
